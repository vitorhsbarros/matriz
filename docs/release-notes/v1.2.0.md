# Matriz 1.2.0 — Release notes

**Version:** `1.2.0`, Git tag `v1.2.0` on `main`, released on 2026-11-16.
**Image:** `ghcr.io/vitorhsbarros/matriz:1.2.0` (also `latest`), for `linux/amd64`, with a signed provenance attestation.
**Previous release:** [1.1.1](v1.1.1.md).

## Version number

A **minor** release over `1.1.1` ([Semantic Versioning](https://semver.org/spec/v2.0.0.html)):
- **new and backward-compatible:** `MATRIZ_DB_URL` accepts a PostgreSQL connection string besides a JDBC URL. Every existing setting works as before;
- **no breaking change:** the API (`openapi.yaml`), the database (no migration) and the features are the same.

## What changed

- **Ready for Render (PD13).** [render.yaml](../../render.yaml) describes the application and its PostgreSQL on Render's free plan. Setting it up is "New → Blueprint", the three demo passwords, and "Apply": see [README.md, "Deploying to Render"](../../README.md#deploying-to-render).
- **A connection string for the database.** Hosting platforms give the database's address as `postgresql://user:password@host:port/database`, which isn't a JDBC URL. `MATRIZ_DB_URL` now accepts that form too:
  - the application turns it into a JDBC URL, without the credentials;
  - the user and password in it are used only when `MATRIZ_DB_USER` and `MATRIZ_DB_PASSWORD` aren't set;
  - an invalid string stops the start-up with a message that names the setting but never shows its value.
- **Checking a deployed application.** With `BASE_URL`, `scripts/image-smoke-test.sh` checks a deployed address. It requires HTTPS and a `Secure`, `HttpOnly` session cookie, and skips the container checks.
- **From the final validation** ([final-validation.md](../final-validation.md)): the image carries Matriz's own labels, the browser application's package has the release's version, and two documents were corrected.

Every change is listed in [CHANGELOG.md](../../CHANGELOG.md).

## Known issues and open points

- **Render's free plan:** the service sleeps after 15 minutes without traffic and takes about a minute to wake up; the database expires after 30 days and has no backups ([deployment-options.md](../deployment-options.md)).
- **No automatic deployment:** a service run from an image is redeployed by hand, or by syncing the Blueprint after changing the tag.
- **amd64 only**, and **the Java runtime isn't scanned**, as in `1.1.1`.
